# 진행 카드 + 완료 보고서 (2026-07-25)

목업 승인: `scratchpad/progress-card-mockup.html`. **선행 작업(글자 흐름 shimmer·경과 시간·재시도 노출·쓴 버튼 숨김)이 끝난 뒤 그 위에 얹는다.**

## 왜

자율 코딩 한 번에 진행 메시지가 10개 넘게 채팅에 쌓여 대화를 밀어낸다. 그런데 정작 필요한 정보는 없다:

- 진행 중인지 멈춘 건지 모른다(실사용: `완성조건 리뷰 중…` 후 **41초 침묵** → 갑자기 완료가 우르르).
- 실패·재시도가 **로그에만** 있어 화면은 침묵한다(실사용: 티켓 2건이 실패→재시도→성공했는데 사용자는 아무것도 못 봄).
- 끝나도 `✓ 코딩 완료: <경로>` 한 줄뿐 — **무엇을 어떻게 했는지, 무엇이 남았는지** 모른다.

사용자 표현: *"그냥 완료만 하면 안 됨"*.

## 무엇을

### 1. 진행 카드(접힘 기본)
한 실행 = **메시지 하나**. 헤더: `⚙ <작업명> — <현재 단계>` + `<경과>초 · <n>/<총>단계` + 셰브론.
- 진행 중엔 제목에 shimmer(선행 작업 결과 재사용), 경과 시간 1초 갱신.
- 클릭하면 단계 목록 펼침. 상태 마커: `✓` 완료 / `◌` 대기·진행 / `↻` 재시도 / `✗` 최종 실패.
- **재시도·실패는 사유와 함께** 단계 아래 보조 줄로(예: `사유: 사용량 한도 — 잠시 후 자동 재시도`). 사유는 `coding-specialist`가 이제 살려 보내는 값(커밋 b252bd8)을 그대로 쓴다.
- 끝나면 헤더가 `✓ 완료 — <n>단계 · <총 시간>`으로 바뀌고 자동으로 접힌다.

### 2. 완료 보고서(별도 메시지)
카드 아래에 구조화된 보고. **AI가 실제 결과를 보고 작성한다**(템플릿 채우기 아님):

| 절 | 내용 |
|---|---|
| 제목 + 리드 | 무슨 작업인지 한 줄 + 대상·브랜치 |
| 무엇을 했나 | 사람 말로 결과 |
| 어떻게 구현했나 | 핵심 판단과 이유(폴링 주기·상한 등) |
| 바뀐 파일 | 경로 + `+n −m` |
| 검증 | 테스트·빌드·타입 통과 배지 |
| **남은 것 · 판단 필요** | 한계·미검증·후속 결정 |
| 액션 | [변경점 보기] [PR 생성] |

마지막 절이 핵심이다 — "완료"만 던지면 한계를 모르고 넘어간다.

## 설계 지침

- **메시지 모델**: 지금은 진행 보고가 `post()` 호출마다 별개 메시지다. 카드는 **하나의 메시지가 갱신**되는 형태여야 한다. 기존 additive 관례(`question`·`toolsUsed`·진행 표시 필드)를 따라 `Message`에 실행 단위 필드를 추가하고, 단계 추가는 **그 메시지의 갱신**으로 처리한다. ⚠️ `chat-store`의 allow-list 등재 필수.
  - 대안(갱신이 어려우면): 실행 id로 묶고 렌더러가 그룹핑. **어느 쪽이든 jsonl 재시작 후에도 카드가 복원돼야 한다** — 휘발 프레임으로만 처리하면 안 된다.
- **회귀 0**: 카드 필드가 없는 기존 메시지는 지금과 동일 렌더.
- 보고서는 **오케스트레이터가 두뇌에게 요청**해 생성한다(코딩 결과·변경 파일·게이트 결과를 재료로). 생성 실패 시 기존 `✓ 코딩 완료` 한 줄로 폴백(절대 침묵 금지).
- 접근성: `prefers-reduced-motion`, 셰브론 키보드 조작, 펼침 상태 aria.

## 검증
