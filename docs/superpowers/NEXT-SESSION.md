## 릴리스하는 법 (한 줄)

```
git tag v0.0.16 && git push origin v0.0.16
```

태그 숫자가 곧 버전이다. CI가 `package.json`·`plugin.json`에 적용 → 3-OS 빌드 → npm 게시(OIDC, 토큰 불필요) → main에 버전 되돌림 커밋까지 자동.
게시만 재시도하려면: Actions → npm-publish → Run workflow → `version=0.0.16`.

**게시는 이제 자동이다**(v0.0.16에서 고치고 **v0.0.17에서 실전 확인** — 드래프트 1개·자산 8개·자동 게시·`latest` 지정까지 사람 개입 0). `desktop-release.yml`이 `draft`(릴리스 하나 선점) → `build`(3-OS가 그 드래프트에 자산만 올림) → `publish`(세 OS 매니페스트 확인 후 `make_latest`로 게시) 순으로 돈다. 사람이 드래프트를 손으로 합칠 일도, `make_latest`를 챙길 일도 없다.
세 OS 중 하나라도 실패하면 `publish`가 아예 안 돌아 드래프트로 남는다(반쪽 릴리스 차단) — 실패한 OS만 재실행하면 이어서 게시된다.

## 회귀 감사 결과(2026-07-30) — 넷 다 고쳐서 v0.0.24로 나갔다

"릴리스만 하고 또 깨진다"는 지적에 17개 에이전트로 감사를 돌렸고, 나온 4건을 전부 고친 뒤 태그했다.

1. **부팅이 영원히 안 끝난다**(내가 v0.0.21에 넣은 회귀). `title: 2026-07-30`은 gray-matter가 **Date**로,
   빈 `category:`는 **null**로 준다 — `parsed.data as PageFrontmatter`는 아무것도 보장하지 않는 거짓말이었다.
   그 값이 지문 계산의 `crypto.update`에 들어가 던졌고, 그 호출이 `try` 밖이라 `reindexAll` 전체가 reject돼
   `onModuleInit`의 `await`가 끝나지 않았다(스플래시가 영원히 남는다).
   - 고친 자리: **`parsePage` 한 곳**(읽는 지점이 여기 하나뿐 — RAG·폴더 트리·화면이 같이 낫는다) + crypto 경계 이중 방어 + 지문 계산을 `try` 안으로.
   - 곁가지 발견: LanceDB `category` 열은 **non-nullable**이라 null이면 그 페이지는 영영 색인되지 않았다(조용히).
   - ⚠️**지문 구분자(`SEP='\0'`)를 바꾸지 마라.** 바꾸면 업데이트한 사용자 전원이 부팅에서 전 페이지를 다시 임베딩한다(13장 약 4분). 원래 코드엔 날 NUL 바이트가 박혀 있어 git이 파일을 binary로 취급했다 — 이스케이프로만 바꿨고 해시는 바이트 동일함을 테스트로 고정했다.
   - 개발 머신에서는 **절대 재현되지 않는다**(앱이 쓴 페이지는 늘 문자열). git 동기화·손편집 페이지에서만 터진다.
2. **낡은 앱이 승인을 삼킨다** — 위 표의 마지막 줄 참조.
3. **승인창이 거짓말** — "(queued as a proposal)"이라 적어 뒤에 검토가 또 있는 것처럼 읽혔다. 실제로는 누르는 순간 게시된다. 승인창·도구 설명·플러그인 명령·README 넷 다 정정.
4. **빈 위키가 백지** — 첫 실행 사용자의 첫 화면인데 "비어 있음"과 "고장"이 구분되지 않았다.

### 이 감사에서 얻은 방법론

- **관측 없이 "고쳤다"고 하지 않는다.** 이번엔 오염된 페이지를 넣은 데이터 폴더로 진짜 부팅 경로
  (`WikiEngine.listPages` → `RagStore.reindexAll`)를 돌려 **HEAD에서 재현**("Received an instance of Date")한 뒤,
  수정본에서 통과(2/2 색인 · 재부팅 2/2 스킵 · 그 페이지도 검색됨)를 눈으로 봤다. 회귀 테스트도 HEAD로 되돌려
  실패하는 것을 확인했다(`git stash push -- <파일>` → 실패 → `stash pop`).
- **테스트의 시간 가정은 CI를 세운다.** 고정 `setTimeout(20)`이 부하 걸린 전체 실행에서 첫 pull보다 먼저 지나갔다
  (v0.0.20 윈도우 CI를 세운 것과 같은 부류). 조건 대기로 바꿨다.
- 격리 재실행 없이 "플레이크"라고 부르지 않는다 — 3/3 통과를 확인하고도 원인(시간 가정)을 찾아서 고쳤다.

## 갈라진 저장소를 **합치는** 코드(2026-07-30, v0.0.25 예정)

경고만 찍고 사용자가 손으로 옮기게 하던 것을 실제 이동으로 바꿨다. 앱이 부팅할 때
`importSplitStorePages`가 샌드박스(패키지 컨테이너)에 갇힌 페이지를 자기 위키로 데려온다.

**왜 앱이 하는가**: 컨테이너 안에서는 진짜 폴더에 쓸 방법이 **아예 없다**. `%APPDATA%` 아래 전체가
가상화 대상이라 경로를 어떻게 적어도 OS가 오버레이로 보낸다. 반면 앱은 가상화 밖이고 그 오버레이
폴더를 읽을 수는 있다. 그래서 고치는 쪽이 앱이다. 앱이 없는 사용자도 커버된다 — 갈라진 저장소를
발견했는데 내 쓰기가 리디렉션되지 않으면(=이 프로세스가 가상화 밖) 헤드리스 코어가 직접 데려온다
(클로드 데스크톱 + 클로드 코드 CLI 조합이 실제로 그렇다).

⚠️**원장(`state/split-import.json`)을 없애지 마라.** 처음 구현은 "대상 파일이 이미 있으면 가져온
것"으로 판정했는데, 원본은 절대 지우지 않으므로 **사용자가 앱에서 지운 페이지가 부팅마다 영원히
되살아났다**(충돌로 남겨둔 페이지는 더 나쁘게 — 낡은 샌드박스 버전으로). 23개 에이전트 적대적
검토가 재현했다. 지금은 원본 바이트의 sha256을 원장에 남기고, 기록된 내용은 대상이 없어도 다시
데려오지 않는다. 충돌도 기록한다(안 하면 지웠을 때 낡은 사본이 올라온다).

그 외 규칙(전부 회귀 테스트 있음): 원본 절대 삭제 안 함 · 이름 같고 내용 다르면 덮어쓰지 않음(앱이
이김) · 막 쓰인 파일은 다음 부팅으로 미룸(SETTLE_MS 3초, 잘린 사본 방지 — 복사 후 mtime·size
재확인) · 파싱 안 되는 파일은 들이지 않음 · 커밋이 성공해야 원장에 기록(실패는 다음 부팅에 재시도)
· never-throw.

**커밋이 필수인 이유**: WikiEngine의 모든 쓰기는 `commitAll(msg, relPath)`로 경로를 지정한다. 파일만
복사하면 영영 untracked로 남아 ①원격에 안 나가고 ②이력에 안 남고 ③나중에 그 페이지를 지우면
`deletePage`의 경로 지정 커밋이 pathspec 오류로 던져 파일은 사라졌는데 색인엔 남는다.

**설정은 가져오지 않는다**(`config/wiki-remote.json` 등). git 원격은 `risk: danger` 확인 게이트를
거치는 설정이다 — 다른 데서 설정된 원격을 앱이 조용히 읽어 위키 전체를 푸시하기 시작하면 그 게이트를
뒷문으로 뚫는 셈이다. 원격은 양쪽에 각각 설정해야 한다.

### 곁가지로 고친 것

- **깨진 페이지 한 장이 부팅을 세우던 경로**: `getPage`는 ENOENT가 아닌 에러를 그대로 던지고
  `readForList`가 안 잡아서 YAML이 깨진 페이지 하나가 `listPages`를 reject시켰다. 목록에서
  떨어뜨리고 부팅은 계속한다(`getPage` 자체의 계약은 유지 — 한 페이지를 콕 집어 열 때는 원인을
  알아야 한다).
- **git 연결의 첫 순간이 "인증 거부"로 보고되던 것**: 브랜치 지정 fetch는 원격에 그 브랜치가 없으면
  던진다(빈 저장소를 처음 붙일 때가 늘 그렇다). 브랜치 없는 fetch로 갈라내 진짜 실패만 실패로 본다.
- 이력이 갈라진 두 위키가 원격에서 합쳐지는 것을 로컬 베어 저장소로 **실측 확인**했다
  (`--allow-unrelated-histories` 경로).

## 해결된 미제 — "위키가 2장만 보인다"(2026-07-27)

**Engram 버그가 아니었다.** 위키가 물리적으로 두 벌로 갈라져 있었다.

- 진짜 `%APPDATA%\engram\wiki\pages\default` → 2장. 앱은 이걸 정확히 읽고 있었다.
- Claude 데스크톱 MSIX 컨테이너(`%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\engram\...`) → 나머지 11장.
- 원인: `npx engram-wiki-mcp`는 앱이 꺼져 있으면 **코어 모드로 자기가 직접 쓴다**. 그 프로세스가 패키지 컨테이너 안에서 돌면 Windows가 `%APPDATA%` 쓰기를 컨테이너로 리디렉션한다. 앱이 떠 있을 때 저장한 2장만 브리지를 타고 앱이 직접 써서 진짜 폴더에 남았다.
- 두 저장소의 `wiki/.git` 이력이 공통 조상 없이 분리돼 있었고 진짜 쪽엔 **delete 커밋이 0** — 지워진 게 아니라 애초에 없었다는 증거.

⚠️**조사할 때 반드시**: 에이전트 셸은 그 컨테이너 안에서 돌아 `%APPDATA%`를 **합쳐진 뷰**(진짜+오버레이)로 본다. 디스크 나열을 진실로 믿지 마라. 진짜는 UNC로 본다 — `Get-ChildItem "\\localhost\C$\Users\...\AppData\Roaming\engram\..."`. `dangerouslyDisableSandbox`로도 안 바뀐다(에이전트 샌드박스≠패키지 정체성).

조치: 11장은 UNC 경로로 진짜 폴더에 복사해 회수(앱이 13장 확인). 컨테이너 원본은 백업으로 남겨둠. 재발 방지로 `src/knowledge-core/wiki/split-store.ts`가 부팅 때 갈라진 저장소를 찾아 양쪽 경로·장수를 로그에 남긴다(앱·헤드리스 둘 다).

## 3순위 — 남은 다듬기

- **독 터미널에서 사람이 직접 `claude`를 띄우면** `ENGRAM_RESIDENT`를 물려받아 앱 내부 호출로 오인 → elicitation 생략. 저장은 승인함으로 가서 안전하나 판별이 부정확하다. 두뇌 스폰 시점에 전용 표식(`ENGRAM_APP_TURN`)을 심는 게 정답(`src/brain/**`).
- **탐색기에서 파일 끌어다 놓기 미검증** — 자동으로 실제 파일 드래그를 만들 수 없어 URL 드롭만 확인했다. 사람이 한 번 확인 필요.
- **m4a/aac 폴더 변환 미지원** — 순수 JS 디코더가 GPL-2.0-only뿐이라 AGPL과 비호환. ①안내만 ②GPL 디코더를 별도 프로세스로 격리 ③유료 API 중 사용자 결정 필요.
- 스캔 PDF(글자층 없음) OCR 경로 없음 — 이미지로 넣으라고 안내 중.
- 진행 카드: 재시도 사유가 별도 보조 줄이 아니라 단계 문구 안에 표시됨(`progressRun.note` 추가로 분리 가능).
- 브라우저 탭을 많이 열면 webview를 전부 살려 둬 메모리가 는다(뒤로가기 보존 대가).

## 작업 규칙(이 레포에서 반드시)

- **UI가 바뀌면 목업 먼저** 만들어 승인받고 구현(위키 UI 참사의 교훈).
- **출하 아티팩트 자체를 검증**하라 — 같은 코드의 다른 빌드로 대체 검증 금지(깡통 설치본 사고).
- 격리 실부팅엔 **`ENGRAM_OPEN_CHAT=1` 필수**(없으면 트레이 전용으로 떠서 가짜 행처럼 보인다). 사용자 앱·`%APPDATA%\Engram`은 읽기 전용.
- **커밋은 경로 명시**(`git commit -m "..." -- <경로들>`) — 남의 스테이징이 딸려간 사고가 있었다.
- 포커스 테스트 실패를 플레이크로 단정하지 마라 — 격리 재실행으로 확정한 뒤 판단.
- **원인을 단정하기 전에 반증을 확인하라** — 오늘 두 번 틀렸다(패닉=크래시, 렌더러 복구 실패).
